# Timelines

Personal tool for finding spoken dialogue to sample. Type words or a sentence into the search prompt
of a dark room with a timeline in it, get clips with the matching line, source, date and timestamp, preview them, and save
them as WAV/MP3. It runs as a web app (`npm run dev`) and as an Electron desktop app (`npm run desktop`); the desktop app
is how other people use it: every source is added with a button, no terminal.

## Commands

- `npm run dev`: API (http://127.0.0.1:4747) and UI (http://localhost:5273, strict port) together.
- `npm test`: unit tests (`server/**/*.test.ts` and `web/src/**/*.test.ts`, Node's built-in runner, no extra deps).
- `npm run typecheck`: `tsc --noEmit` over `server/` and `web/src/`.
- `npm run build` then `npm start`: serves the built UI from the API server on :4747.
- `npm run desktop`: builds the UI and opens the Electron app with its own empty data folder (the library a new user would see). `TIMELINES_DATA=$PWD/data npm run desktop` opens it on the developer library instead. `TIMELINES_SMOKE=/some/folder` (with `electron .`) writes a screenshot and a health report there and quits; `TIMELINES_DEVTOOLS=1` opens the dev tools.
- `npm run dist:win` (on Windows) / `npm run dist:mac` build installers into `release/` with electron-builder (`electron-builder.yml`); the GitHub workflow `.github/workflows/desktop.yml` does it on a tag. Nothing is signed (see `.claude/rules/desktop-app.md`).
- `npm run ingest -- <ia|podcast|peoples-speech|peoples-speech-films|stats|retitle> ...`: add recordings to the index (see `server/ingest.ts` usage). `retitle` recomputes Internet Archive titles and dates from stored file names, with no re-transcribing.
- After replacing or deleting `data/timelines.sqlite` (libraries made under the old name keep `data/back-then.sqlite`), restart the API (`touch server/index.ts` under `npm run dev`); it keeps the old file open otherwise.
  Example: `npm run ingest -- ia --query 'collection:oldtimeradio AND subject:"science fiction"' --limit 4 --per-item 2 --topic sci-fi --max-minutes 10`

Node 24+ runs the TypeScript in `server/` directly (type stripping), so there is no server build step.
That means server code must use erasable syntax only (no enums, no parameter properties) and import
with `.ts` extensions.

## Layout

- **Adding sources (what the desktop app is built around).** `server/jobs.ts`: `JobRunner`, background imports that can be paused and resumed (tables `jobs`, `job_items`; one job at a time, items one after another; pausing aborts the running item, which goes back to "waiting"; a processor may `addItems`, `peekWaiting`, throw `JobStop` to pause the job with a message; closing the app pauses what was running). Unit-tested with fake processors. `server/importers/`: one importer per kind of job, each with a planner (works out the items; throws a message fit for the user) and a processor: `ia.ts` (an Internet Archive search; takes the MP3 or else the smallest video file, `pickPlayable`), `podcast.ts` (latest episodes of a feed), `files.ts` (files and folders from the user's disk, stored as `file:` URLs; a `.srt`/`.vtt` next to a file is used instead of transcribing; `subtitles.ts` parses them), `films.ts` (the People's Speech films, one item per shard), `common.ts` (`transcribeAndSave`: checks the tools are installed, transcribes, records the speed, saves), `peoplesAudio.ts` (joining clips into one FLAC), `index.ts` (`planJob`, `buildProcessors`). `server/setup.ts`: whether ffmpeg, the whisper engine and a speech model are there; on Windows it installs them itself (ffmpeg from the BtbN builds, whisper.cpp from its GitHub release, the CUDA build when `nvidia-smi` answers, models from Hugging Face), on a Mac it shows the `brew install` command. `server/models.ts`: the three downloadable models (Best/Balanced/Fast). `server/settings.ts`: `settings.json` in the data folder (Podcast Index key and secret, chosen model, measured transcription speed; secrets are never sent back to the page). `server/exec.ts`: `run` (abortable, hides the console window on Windows) and where each tool lives (`TIMELINES_BIN_*`, a bundled folder, `data/bin/`, else PATH). `server/download.ts`: download with progress. `server/guard.ts`: with `TIMELINES_TOKEN` set (the desktop app does this) every request needs a cookie that the window gets from `/?token=` once, and the Host header must be 127.0.0.1 or localhost on this port. API: `/api/jobs` (+ `/:id`, `/:id/pause|resume|cancel`), `/api/events` (server-sent events with the jobs and the setup state), `/api/setup`, `/api/setup/install`, `/api/settings`, `/api/sources/ia/preview`, `/api/sources/podcasts/search`, `/api/sources/files/preview`, `/api/sources/films`.
- `desktop/main.mjs`, `desktop/preload.cjs`: the Electron shell. It picks a free port, starts the server as a utility process (`server/index.ts` runs directly: Electron 45 ships Node 24, which strips types and has `node:sqlite`), waits for it, and opens a window on `http://127.0.0.1:<port>/?token=...`. Data lives in the user's app data folder (`TIMELINES_DATA`). The preload exposes `window.backThen` (`pickFiles`, `pickFolder`, `pathForFile` for dropped files); links to other sites open in the browser. `web/src/sources/`: the "Add sources" panel (`SourcesPanel.tsx`, `forms.tsx`, `sourcesApi.ts` with the `useEvents` hook, `presets.ts` with the Internet Archive presets and the time estimates, unit-tested). `seed/peoples-speech-films.json`: the list of People's Speech films that ships with the app.
- `server/index.ts`: HTTP API (`/api/search`, `/api/topics`, `/api/context`, `/api/segments` (transcript segments overlapping a time range, for the editor), `/api/timelines` (saved timelines, see below), `/api/clip` (optional `fi`/`fo` fades in ms, `raw=1` to skip the automatic declick), `/api/bounce` (joins clips into one WAV/MP3, keeping each clip's fades), `/api/health`) and static serving of `web-dist/`.
- `server/timelines.ts`: saved timelines (`timelines` and `timeline_clips` tables; unit-tested with an in-memory database). A timeline is a named collection of starred clips; one timeline is one story today. Routes in `server/index.ts`: `GET/POST /api/timelines`, `GET/PATCH/DELETE /api/timelines/:id` (PATCH takes `name` and/or `story`), `POST /api/timelines/:id/duplicate`, `POST /api/timelines/:id/clips`, `PATCH /api/timelines/:id/clips?key=` (replace a clip's snapshot after trimming, keeping its key), `DELETE /api/timelines/:id/clips?key=`. A timeline also stores its story settings (`story` column: clip order, muted clips, gap); `openDb` adds columns that older databases lack (`migrate`, additive only). Writes must be `application/json` (a page on another site cannot send that without a CORS preflight, which the server never answers).
- `server/singleflight.ts`: runs one job per key at a time (unit-tested). `server/bounce.ts`: the story file: validates a clip list (`parseBounce`, unit-tested), cuts each clip as WAV with `cutClip`, joins them with silence between (ffmpeg concat), caches the result. Only `ep:` refs resolve.
- `server/db.ts`: SQLite (`node:sqlite`, file `data/timelines.sqlite`, or `data/back-then.sqlite` in a library made under the old name: `config.ts` keeps using that file while the new one does not exist): `episodes`, `episode_topics`, `segments` plus an FTS5 table `segments_fts` (porter stemming). External-content FTS: deleting an episode must also delete its FTS rows (see `deleteEpisode`).
- `server/sources/library.ts`: searches the local index. Query goes phrase, then AND, then OR; each hit is widened by one segment each side; `expandWindow` widens more.
- `server/sources/gdelt.ts`: live TV caption search (GDELT TV API, needs `market:"National"`, takes 10-20 s; a failed request is tried once more, then the error says GDELT did not answer twice and why; unit-tested with an injected `fetch`).
- `server/sources/internetArchive.ts`, `server/sources/podcastIndex.ts`: clients used by ingest.
- `server/sources/peoplesSpeech.ts` (pure, unit-tested: clip ids, readable names and dates, FLAC length from the header, laying clips end to end) and `server/sources/peoplesSpeechShard.ts` (downloads a parquet shard and reads it one row group at a time with `hyparquet`). `npm run ingest -- peoples-speech [--config microset|clean|dirty] [--shard N]` indexes a shard of the People's Speech dataset: no transcription, since it ships transcripts. A recording's ~15 s clips are joined into one local FLAC in `data/peoples-speech/audio/` and become one episode (`source: 'peoples-speech'`, `audio_url` is a `file:` URL) with one segment per clip; times come from the FLAC headers so they match the audio exactly (verified sample by sample against the original clips). The `microset` (336 clips, one 79 minute recording) is indexed.
- `server/sources/peoplesSpeechFilms.ts` + `npm run ingest -- peoples-speech-films`: the film part of People's Speech `clean`. The dataset has no labels, so films are picked by Internet Archive collection (`FILM_COLLECTIONS`: prelinger, feature_films, moviesandfilms, film_scifi, SciFi_Horror, Film_Noir, Comedy_Films): the collections are scraped from the Archive and intersected with `data/peoples-speech/catalog-clean.json` (every recording of the set with its clip count, milliseconds and first shard, from a full scan), the same scrape returns each item's title, date and subjects (one request per 10,000 items; per-item metadata calls were about 2 s each), and the result is kept in `films.json` (built once; `--refresh` rebuilds). The import then goes shard by shard: download (about 470 MB), keep only the film clips (`readShardRows` reads the ids first and decodes audio only for row groups that hold a film), assemble one FLAC per recording, save the episode (`show` is "Prelinger Archives" or "Public-domain film", `title` the film's title, `date` its year, topics `film` plus `prelinger`, `sci-fi`, `horror`, `film-noir`, `comedy`), delete the shard. A film that runs into the next shard queues it and becomes a second episode titled "(cont.)". Progress is in `films-done.json`, so it can be stopped and restarted. `--select-only` builds only the list; `--shard N` imports one shard.
- `server/ingest.ts` (the command line, now a thin wrapper over the importers), `server/whisper.ts`: ffmpeg streams the source to 16 kHz WAV, `whisper-cli` (whisper.cpp) transcribes it (`transcribeTimed`: abortable, reports stage and speed, tries the graphics card only when the app installed the CUDA build and falls back to the processor for the session if it fails), segments go into SQLite. Topics come from source metadata (`server/topics.ts` normalises spellings) plus the topics the user typed.
- `server/naming.ts`: broadcast date and readable title from Internet Archive file names.
- `server/clip.ts`: cuts a clip, cached in `data/clips/`. Only `ep:<id>` refs resolve, so the endpoint is not an open proxy. For constant-bitrate MP3 it fetches just the clip's bytes with one HTTP Range request (the resolved URL and layout are cached 15 minutes; `/api/search` warms the top 3 episodes) and ffmpeg trims the exact start; anything else falls back to ffmpeg on the resolved URL.
- `server/fade.ts`: fade limits and the ffmpeg `afade` filters. Pure, and also imported by the web code (an exception to "web imports server types only") so the editor and the export agree. A clip's fades are `Hit.fadeInMs`/`fadeOutMs` (absent = none). Every export also gets a 5 ms **declick** fade at both ends (`withDeclick`; the editor's own audio window is loaded with `raw=1` to avoid it); `Voice` applies the same floor and ramps down on stop, so what you hear is what you save.
- `server/mp3.ts`: the MP3 header parser behind that (`id3Length`, `cbrLayout`: constant-bitrate check and the measured byte rate). Unit-tested.
- `web/src/`: React UI, a dark "room" with two phases (`data-phase` on `.room`): **idle** (prompt up top, the timeline panel starts mid-room and reaches the bottom edge, so no strip is left empty under it; the line keeps its place through `idleLineRatio` in `timeline/model.ts`, which the engine eases like any other line ratio) and **active** (prompt moves up, results fade in, timeline docks to the bottom; `t` enlarges the dock). Layout changes are CSS transitions on `top`/`height` driven by variables in `styles.css` and `timeline/timeline.css`.
  - `App.tsx`: state, search, shortcuts, the pin flow (`pin()` flies a dot from the star button while the timeline camera moves, then adds the clip) and `trim()` (keeps a trimmed range and the transcript text inside it). `ResultCard.tsx`, `PinCard.tsx` (popover for a pinned clip), `fly.ts` (the flying dot, Web Animations API), `icons.tsx`.
  - **Playback and trimming.** `audio.ts`: shared Web Audio context, `decodeUrl`, and `Voice` (plays an exact span of a decoded buffer, loops, only one voice plays at a time: starting one stops the other). `usePlayer.ts`: loads a clip plus 8 s each side as one decoded window and the transcript segments inside it; exposes the live `region`. `ClipEditor.tsx`: the Ableton-style waveform (drag an edge to trim, outward too; drag the square at the top of an edge to fade in or out; drag the middle to slide; click to play from a point; edges snap to sentence boundaries, hold Alt to place freely; read-only mode in the popover). `trim.ts`: its pure logic (`windowFor`, `buildPeaks`, `snapTime`, `dragEdge`, `moveRegion`, `selectText`), unit-tested. `dragClip.ts`: drag a clip out as a WAV (`DownloadURL`).
  - **Story** (`story/`): `useStory.ts` takes the library clips on the timeline in the saved order (`settings.ts`: `applyOrder`, muted clips left out, gap; unit-tested), fetches and decodes them (3 at a time, decoded buffers cached), stitches one stereo buffer with `STORY_GAP_MS` (400 ms, shared with the server) between clips, and plays it with `Voice`; opening it auto-plays once loaded. `StoryPanel.tsx`: the waveform that grows out from the middle while loading, a row of clip chips (drag to reorder, the eye leaves a clip out, click plays from it), the gap stepper, play/pause, clock, WAV/MP3 download (`/api/bounce`). Rebuilds from already decoded clips are immediate, without the loading animation. `layout.ts`: where each clip sits and which one is playing (unit-tested). While it plays the timeline camera visits each clip's node (`is-now`).
  - `timeline/model.ts`: pure date/tick/zoom maths (unit-tested): `parseDate`, `pinKey`, `pinTime`, tick levels, `fitView`, `planView`. `timeline/engine.ts`: canvas drawing, pan with inertia, wheel/pinch zoom, `flyTo` with a zoom-out arc; it positions the DOM nodes itself each frame (transform, `--prox`), so React must not set `transform` on `.node`. `timeline/Timeline.tsx`: the component and its imperative handle (`viewKey` = which saved timeline is showing: the first one plays the opening shot, later ones fly the camera to the new clips; `titleSlot` holds the switcher) (also the Play story button, the `footer` slot for the story panel, and `lineRatio`, which moves the line up to make room for it). `timeline/useTimelines.ts` + `timelinesApi.ts`: the saved timelines and the clips of the open one, kept on the server (optimistic updates, rolled back with a notice if the save fails); the open timeline id is remembered in `localStorage` (`timelines.active-timeline`). The first time the server has no timelines, the clips this browser had in the old `timelines.timeline` localStorage key are imported as "My first story" and the key is removed. `timeline/TimelineSwitcher.tsx`: the name in the dock and its menu (switch, new, rename, duplicate, delete; there is always at least one timeline).
  - `theme.ts`: dark by default ("lights off"), light theme is "lights on", remembered in localStorage. The theme attribute is set in a layout effect because the timeline canvas reads `--ink`/`--accent` from CSS when the theme changes.
  - `format.ts` (time/date formatting and search-term highlighting, unit-tested), `styles.css` and `timeline/timeline.css` (colours are RGB triples `--ink`/`--accent` so any alpha works: `rgb(var(--ink) / .4)`).
- Shared types live in `server/types.ts` and are imported by the web code as types only.

## Secrets and data

- `.env` (git-ignored; template in `.env.example`): `PODCAST_INDEX_API_KEY`, `PODCAST_INDEX_API_SECRET`, `IA_S3_ACCESS_KEY`, `IA_S3_SECRET_KEY`. Never commit it or print its values. Values containing `$` or `^` must be single-quoted. The desktop app does not use `.env`: the Podcast Index key is entered in its Add sources screen (saved in `settings.json` in the data folder).
- `data/` is git-ignored: the SQLite index, Whisper model, cached clips, logs.
- Whisper model: `data/models/ggml-large-v3-turbo-q5_0.bin` (download from `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin`, override the path with `TIMELINES_WHISPER_MODEL`).
- External tools from Homebrew: `ffmpeg`, `whisper-cpp` (`whisper-cli`).

## Things that are not obvious

- **Whisper runs on CPU.** Homebrew whisper.cpp 1.9.5 aborts in its Metal backend on this Mac (ggml scheduler assertion, every model). `server/whisper.ts` passes `-ng`; set `TIMELINES_WHISPER_GPU=1` to try the GPU again after an upgrade. CPU speed is about 2.3x real time with the large-v3-turbo q5_0 model.
- **ffmpeg misdetects some Internet Archive MP3s as WAV** (an ID3 tag containing "RIFF"), so `.mp3` URLs are opened with `-f mp3` (`inputFormatArgs`).
- **Clip byte rate is measured, not nominal.** Some encoders never pad frames, so a "64 kbps" file can run at 7962 bytes/s; trusting the nominal rate put clips 1.9 s off. `cbrLayout` reads the padding bits. See `.claude/rules/roadmap.md` for the verification and for hosts that serve different audio per User-Agent.
- **Anything that writes into `data/clips/` runs through `singleflight` and writes to a unique temporary name before an atomic rename** (`cutClip`, `bounce`, the silence file). Overlapping identical requests used to share one `.part` file and one of them could rename a truncated 252-byte file into the cache, where it was then served forever ("unable to decode audio data" in the story). Dev mode makes it likely: React StrictMode starts the story load twice, and the server keeps cutting after the first request is aborted. A new cache-writing path must do the same.
- **`hyparquet` returns binary columns as text unless `utf8: false`.** The audio column then comes back as a string and the bytes are silently mangled (length changes, the FLAC header is destroyed); with `utf8: false` the id and transcript are still strings and the audio is a `Uint8Array`.
- **A hit is widened with its neighbouring segments only when the matching segment is short** (under 8 s, `LONG_SEGMENT_MS`). Whisper segments are a few seconds; People's Speech clips are about 15 s, and three of them would be a 45 s hit.
- **Local recordings are cut straight by ffmpeg** (`file:` URLs in `clip.ts`): FLAC seeks exactly, so none of the byte-range machinery applies.
- **Fades are baked in on export, heard through gain automation in the editor.** `Voice` ramps a `GainNode` (loops schedule each pass 2 s ahead on a timer); `/api/clip` applies the same linear ramps with ffmpeg. With a fade the fast clip path trims inside the filter chain (`atrim` + `asetpts` + `afade`), because ffmpeg applies output-side `-ss` after the filters and the fade would land before the cut. Story playback loads each clip with its fades from the server.
- **A saved clip has a stable `key` (its original `pinKey`); trimming it later changes its `hit` but not its key.** That keeps its DOM node (no re-animation) and its place in the story order. Whether a result is starred is decided by comparing `pinKey(hit)` with `pinKey(saved.hit)` (`useTimelines().find`), not by key.
- **Same-day clips fan out on the timeline** (`spreadPositions`, 22 px apart, computed each frame in `engine.ts`), so a dot can sit a little off its date; crowded dots show only their number until hovered or at the playhead.
- **Dragging a clip into a DAW** uses the `DownloadURL` drag type: Chromium browsers (Chrome, Brave, Edge) turn it into a real file when dropped on Finder or the desktop, and apps that accept file drops take it from there. Safari and Firefox do not support it; use the wav/mp3 buttons there. A native drag needs the Tauri/Electron wrapper.
- **The editor plays from a decoded window, not an `<audio>` element**, so edges are sample-accurate and loops work. The window comes from the same `/api/clip` endpoint (clip ±8 s); clip cutting accuracy is described in `.claude/rules/roadmap.md`.
- **TV clips are stream-only.** Internet Archive TV news video files return 401, so they cannot be cut, waveformed or saved. TV hits play in the archive's embedded player (`archive.org/embed/<id>?start=&end=`), and have no WAV/MP3 buttons.
- **Dates**: old-time-radio broadcast dates are parsed from file names (`server/naming.ts`) because IA's `date` is the upload date. The timeline pins saved clips by this date (undated clips use the day they were saved).
- **Testing against a copy of the database:** `TIMELINES_DB=/path/copy.sqlite TIMELINES_PORT=4848 node --env-file=.env server/index.ts`, plus `TIMELINES_PORT=4848 npx vite --port 5274` for the UI. Do this for anything that writes timelines: the real database holds the owner's saved timelines, and the owner may have their own dev server running (`npm run dev` with `--watch` reloads server code automatically).
- **The app has had three names: telly, then Back then, and since 2026-11-12 Timelines.** `web/index.html` copies old `telly.*` and `back-then.*` localStorage keys to `timelines.*` once, so saved clips and settings survive; the desktop app renames the old `Back then` app data folder to `Timelines` on first start; `config.ts` keeps an existing `back-then.sqlite`. The environment variables are `TIMELINES_*` (they were `BACK_THEN_*`). The GitHub repository is `davidnb3/timelines-sampler` (renamed by the owner on 2026-11-12; GitHub redirects the old `back-then` address). The working folder may still be called `back-then` on the owner's Mac. **The wordmark** in the top bar is Instrument Serif italic, bundled with `@fontsource/instrument-serif` (SIL Open Font License), imported in `web/src/main.tsx` and styled in `.brand-name`.
- **Port 5173 belongs to another project** on this machine, hence the UI uses 5273 with `strictPort`.
- **`.room` uses `overflow: clip`, not `hidden`.** A hidden box can still be scrolled by `focus()` (the auto-focused prompt shifted the whole room by a few pixels while its entrance animation ran); clip cannot scroll.
- Segment-level hits are intended: results are whole lines of dialogue plus context, not single words.
